Part 1

Build the table and work with it

A table is one group of students. It always has three fixed columns (name, student phone, parent phone).

Tables
GET/api/tracking-tables?deleted=false

The teacher's tables. Use deleted=true for the trash view.

Response

   "rows": 32, "columns": 6, "isDeleted": false,
   "createdAt": "…", "updatedAt": "…" }]

Columns
POST/api/tracking-tables/{groupId}/columns

Add a column. The type decides the input to show in a cell.

Body
{ "name": "امتحان 1", "type": "Exam", "maxScore": 20 }
{ "name": "الحضور", "type": "Number" }
{ "name": "المستوى", "type": "Choice",
  "options": ["ممتاز", "جيد", "ضعيف"] }
Types → cell input
Text    → text box (up to 500)
Number  → number
Date    → date picker
YesNo   → toggle
Choice  → dropdown of options
Exam    → score 0…maxScore, or "absent"

Multipart: file, groupName and optional options (JSON text) to override what was recognised.

POST/api/tracking-tables/{groupId}/export

Download the table as .xlsx. The body takes the same search / filters / sort as the query; an empty body exports everyone.

Response
200 · application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Right-to-left sheet, phones as text (leading 0 kept),
exams as numbers or "غائب"

Read the response as a file (blob) and save it. It is not JSON.

Part 3

Reports to parents

GET/api/tracking-tables/report-templates

The templates the teacher can send. An empty list means sending is off: hide the "Send report" button.

Response
[{ "key": "exam_result", "label": "نتيجة امتحان", "blanks": 4,
   "body": "ولي أمر الطالب {{1}}، نتيجة {{2}} في {{3}}: {{4}}" }]
POST/api/tracking-tables/{groupId}/reports

Build the report and get a preview. One source per blank, in order.

Body
{ "templateKey": "exam_result",
  "blanks": ["studentName", "text:امتحان 1",
             "teacherName", "c4"],
  "rowIds": null }
// sources: studentName | groupName | teacherName
//          | a column id | "text:…"
// rowIds null = every student
Response · preview
{ "batchId": "7f3c…", "ready": 30, "skipped": 2,
  "quota": { "needed": 30, "remaining": 120, "code": null },
  "messages": [{ "rowId": 11, "student": "أحمد علي",
     "phone": "01000001001",
     "text": "ولي أمر الطالب أحمد علي، نتيجة امتحان 1 في مستر محمد: 18 / 20" }],
  "skippedRows": [{ "rowId": 14, "student": "منى",
     "reason": "no_parent_phone" }] }

Skip reasons: no_parent_phone, no_messages, empty_value (with the blank number). If quota.code is not_in_plan, show the teacher bundles before they try to send.

Part 4

The rest

Report history, teacher bundles, the admin screen, and the error-code list.

GET/api/tracking-tables/reports

Every report sent, newest first, with counts per status. Tap one to open its detail.

Response
[{ "batchId": "…", "groupName": "السبت 4 م", "template": "نتيجة امتحان",
   "createdAt": "…", "counts": { "sent": 28, "failed": 1, "skipped": 2, … } }]
GET/api/tracking-tables/bundles

Teacher bundles (they include parent messages). Show them on not_in_plan or quota_exhausted; buy through the normal /api/subscription/preview → /api/subscription/purchase flow.

GET/api/tracking-tables/admin/teachers
PUT/api/tracking-tables/admin/teachers/{userId}/messaging

Admin panel only (Support, Manager, Admin): list teachers, and block or allow their messages to parents.

List response

   "tables": 4, "messagesThisMonth": 230, "messagingAllowed": true }]

GET/api/lookups/error-codes

Every error code with its status, group and Arabic message. No login needed. Load once and look up error.code.

Response
[{ "code": "invalid_phone", "status": 400, "group": "TrackingTables",
   "message": "رقم الموبايل غير صحيح" }, …]

Teachers get their role from an admin (PUT /api/admin/users/{userId}/role) or by being linked to a partner. There is no self sign-up endpoint.
