Distraction Blocker API

The server keeps the student's blocker settings and schedules, and a log of every block that actually ran. The phone decides when a time window starts (it knows the local clock and must work offline), blocks the apps and websites, and reports each block's start and end. A mentor can lock the settings so changes need a code.

  • Numbers, not words: days are 0 = Sunday … 6 = Saturday. Draw the day picker from GET /api/lookups/week-days (Part 2). trigger and endReason are numbers too (tables below).
  • Times of day go in as "17:00" and come back as "17:00:00". They're the phone's local wall-clock times.
  • Moments (startTime, endTime, plannedEndTime, createdAt) are UTC. Some come back without a Z, e.g. "2026-10-28T17:04:10.427". Treat those as UTC too, or the app will be 2–3 hours off.
  • While a block runs, PUT settings, PUT schedules/{id} and DELETE schedules/{id} are refused with block_running. A block counts as running until it's ended or its planned end passes; a plan block with no planned end counts for 24 hours at most.
  • Guests can use the blocker. Their responses also carry the usual guest reminder header.

How it works

sequenceDiagram
  participant App as Student's phone
  participant API as Motqin API
  App->>API: GET settings and GET schedules
  Note over App: compares the local clock with each schedule
  App->>API: POST sessions/start (trigger, schedule, planned end)
  API-->>App: the block's id
  Note over App: blocks every app except the allowed ones, and the blocked websites
  App->>API: PUT sessions/id/end (endReason)
  API-->>App: the finished block with its minutes

Part 1

Settings

What gets blocked and when, apart from schedules: during study sessions, during breaks, the automatic plan block, the apps that stay usable, and the blocked websites.

GET/api/distraction-blocker/settings

The student's settings. A student who never saved any gets the defaults below.

200
{
  "success": true,
  "message": "Distraction blocker settings retrieved successfully.",
  "errors": null,
  "data": {
    "blockDuringStudySessions": false,
    "unblockDuringBreaks": true,
    "autoStartPlanBlock": false,
    "allowedApps": [],
    "blockedWebsites": [],
    "lockedByMentor": false,
    "unlockedUntil": null
  }
}
The fields
  • blockDuringStudySessions: block while a study session runs, even outside every schedule.
  • unblockDuringBreaks: with the above on, lift the block during the session's break.
  • autoStartPlanBlock: the app starts the day's "until the plan is done" block by itself at midnight.
  • allowedApps: Android package ids that stay usable; every other app is blocked. iOS app picks never reach the server.
  • blockedWebsites: hosts, e.g. youtube.com.
  • lockedByMentor / unlockedUntil: the mentor lock (Part 4). Read-only.
ErrorsOnly the common ones.

Part 2

Schedules

Two kinds. A time window blocks between two times on chosen days; an end before the start crosses midnight. An until the plan is done schedule blocks the whole day on chosen days and lifts once today's plan and due reviews are finished. Each day can have only one active plan schedule.

Part 3

Blocks (what actually ran)

The app reports each block it runs, so the server knows how long the student was blocked and why it ended. Only one block runs at a time. While a block runs, the settings can't be changed and schedules can't be updated or deleted (block_running); adding a schedule still works.

triggerStarted byblockScheduleIdplannedEndTime
0 ScheduleA time-window scheduleRequired: a time-window scheduleThe window's end, in UTC
1 PlanBlockAn "until the plan is done" scheduleRequired: a plan scheduleMust be left out
2 StudySessionA running study sessionMust be left outOptional
3 ManualThe student, by handMust be left outOptional
endReasonMeaning
0 WindowEndedThe time window finished
1 PlanCompletedToday's plan was done
2 SessionEndedThe study session ended
3 StoppedByUserThe student stopped it
4 InterruptedSet by the server: a new block started while this one was still open (the app was killed or the phone was off)

Part 4

The mentor lock

If the student gave one mentor the lock privilege, then changing settings, updating a schedule and deleting a schedule are refused with blocker_locked. Adding a schedule and starting or ending blocks still work. A code from the mentor allows changes for 15 minutes. The Mentors & Sign-in guide covers the mentor side.

POST/api/mentorship/blocker-unlock/request

Ask for a code. It appears on the lock-holding mentor's page for 10 minutes; asking again keeps the same code.

Part 5

Manual test in Swagger

About 15 minutes with one account. Moments are UTC, so set plannedEndTime to an hour from now in UTC (Egypt time minus 2 or 3 hours).

  1. sign inPOST/api/auth/test-phone-login

    Copy token, click Authorize and paste it.

  2. GET/api/distraction-blocker/settings

    The defaults, or the account's saved settings.

  3. PUT/api/distraction-blocker/settings
