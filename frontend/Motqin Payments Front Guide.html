How this guide is organized

The page follows the backend's controllers. Each controller is a coloured band, and every endpoint under it is one card laid out the same way, so you always know where to look.

One endpoint card, top to bottom
PartWhat it tells you
1. Header lineThe method (GET POST PUT DELETE), the path with its query or {id}, and on the right who can call it: anyone, registered user, guest, teacher or above, manager, admin.
2. BriefOne or two sentences: what the endpoint is for and which screen uses it.
3. Fields tableEvery input: path value, query parameter or body field, with whether it's required, its allowed range and what it means. Endpoints with no input have no table.
4. Valid casesOne block per kind of success, each with the request body (or URL) and the real response. When a block shows two boxes side by side, the left is what you send and the right is what you get.
5. Bad casesA table with one row per mistake: Send (the body or situation that causes it) · Get (the status and the response) · Show (the Arabic message for that code, the same text GET /api/lookups/error-codes returns).
6. Lookups and dependenciesThe other endpoints this one needs, e.g. where a bundleId or partnerId comes from.
7. NotesHow to build the screen: what to show, which button to disable, when to refetch.

Lookups and dependencies
GET /api/lookups/error-codesevery code with its status and Arabic message: show the message for error.code, never error.message (English, for developers).
  • Money is EGP, a number with up to 2 decimals (49.0, 12.5).
  • Times ending in +00:00 or Z are UTC. Some fields (createdAt, updatedAt) have no zone: they're UTC too, so add Z before converting to local time.
  • Enums travel as text: kind Guest/Free/Paid · audience Student/Teacher/Mentor · access Off/Limited/Unlimited · type Usage/Allowance/Access · status of a subscription Scheduled/Active/Expired/Replaced · of a payment Pending/Succeeded/Failed/Expired · operation Purchase/Renewal/Upgrade/Downgrade/Scheduled.
  • Coupon codes are stored without dashes or spaces and in capitals: DOC100-56451 is saved and shown as DOC10056451, and either spelling works when typed.

Lookups and dependencies
GET /api/subscription/meto mark the plan the user is on.
  • Group the cards by plan (the part of title before " · ", or code before the dash) and offer the three terms as a switch.

    1. Choose Card, enter the main card and pay. If a 3-D Secure or OTP page appears, confirm it: it's Paymob's simulator.
    2. Paymob redirects to /api/payment/client-callback ("Payment Successful"). That page changes nothing; ignore it.
    3. Paymob's server calls /api/payment/server-callback on the hosted server, which credits the wallet.
    4. Go on to the next step: the status turns Succeeded with receivedAmount 50 and paymentMethod card.

    Locally the top-up stays Pending, because Paymob can't reach a local server. The checkout link expires after 1 hour; after that the status is Expired and you start a new top-up. Paymob lists no "declined" test card: to see Failed or Expired, cancel the checkout or let it expire. Source: Paymob test credentials.
